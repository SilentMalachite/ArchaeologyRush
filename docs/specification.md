# ArchaeologyRush 仕様ページ

最終更新日: 2026-05-02
ステータス: 実装進行中

## 1. 目的

- このドキュメントは、ゲーム実装の基準となる仕様を定義する。
- 考古学ドメイン仕様はユーザー確定値を基準に実装する。

## 2. スコープ

- 対象: ArchaeologyRush のコアゲームループ、データモデル、UI要件、品質要件
- 非対象: 実装詳細コード、未合意の考古学ルール

## 3. 用語集

| 用語 | 定義 | 備考 |
| --- | --- | --- |
| 発掘ターン | ゲーム内の1日分に相当する行動単位 | 1ターンで3アクション実行 |
| 層（Layer） | 土の層区分。深さと年代仮説を持つ | 上層ほど新しい |
| 遺物（Artifact） | 発見・回収・記録の対象物 | 土器片、石器、骨片、人骨、住居跡など |
| 記録（Catalog） | 遺物や層情報を台帳化する処理 | 記録完了で評価加点 |

## 4. ゲーム目標

- プレイヤーの達成目標: 制限ターン内に重要遺物を3点以上、記録欠落なしで回収する。
- 失敗条件: ターン上限到達時に重要遺物が3点未満、または重大な記録漏れが2回以上。
- クリア条件: 目標遺物数達成かつ最終レポートの必須項目が100%入力済み。
- 評価指標（スコア/品質）: 回収点 + 記録品質点 - 層破壊ペナルティ。

## 5. ゲームループ（1ターン）

1. 事前情報確認: 現在層、残り行動回数、未記録遺物数を確認。
2. 行動選択（例: 掘る/記録/回収）: 1アクションごとに `dig` / `catalog` / `recover` を選択。
3. 結果反映（状態更新）: 層深度、遺物状態、行動回数、スコアを更新。
4. ログ出力: 行動内容と成否理由をターンログに追記。
5. ターン終了判定: 残り行動0でターン終了。ターン上限または目標達成でゲーム終了。

## 6. ルール仕様（ユーザー確定）

### 6.1 発掘ルール

- 掘削可能条件: 対象セルが未掘削、行動回数が残っている、かつ道具耐久が1以上であること。
- 掘削コスト（時間/体力/道具耐久など）: 1回掘削で行動1消費、道具耐久-1。
- 道具耐久0時の扱い: 掘削不可。状態を変更せず、画面に「道具耐久がありません」を表示する。
- 禁止行為/ペナルティ: 同一ターンに同一セルを3回以上掘削した場合、層破壊ペナルティ-5。

### 6.2 層位ルール

- 層の生成/構成方法: 各発掘区画に上層・中層・下層の3層を初期配置。
- 上下関係の制約: 原則として上層から順に掘削し、未開放の下位層は操作不可。
- 破壊・混入の扱い: 不適切な連続掘削で混入フラグを立て、該当層の評価を減点。

### 6.3 遺物ルール

- 種別一覧: `pottery_shard`, `stone_tool`, `bone_fragment`, `feature_mark`.
- 発見条件: 層と座標ごとの確率テーブルに基づき `dig` 成功時に抽選。
  - 基本値: 上層10%、中層25%、下層40%。
  - 例外セル: なし。
- 回収条件: 発見済みかつ記録必須項目のうち「位置」「深度」を入力済み。
- 重要遺物: `pottery_shard`, `stone_tool`, `bone_fragment`。
- 非重要遺物: `feature_mark`。
- 保存状態/価値評価: 種別ごとの基礎点に `poor` / `fair` / `good` / `excellent` の4段階の品質倍率を適用。
  - 基礎点: `pottery_shard` 8点、`stone_tool` 12点、`bone_fragment` 15点、`feature_mark` 2点。
  - 品質倍率: `poor` 0.5、`fair` 1.0、`good` 1.5、`excellent` 2.0。

### 6.4 記録・検証ルール

- 必須記録項目: 遺物ID、座標、深度、層ID、発見ターン、担当者メモ。
- 記録漏れ時の影響: 未記録でターン終了した遺物は一時保留となり回収不可。
- 検証フロー: `catalog` 実行時に必須項目チェック -> 不足表示 -> 再入力。

## 7. データ要件（実装前提）

### 7.1 エンティティ候補

- `Excavation`
- `Layer`
- `Artifact`
- `TurnLog`
- `SiteState`

### 7.2 保存要件

- 永続化対象: 発掘セッション、層状態、遺物、確定済み記録、終了ターン結果。
- 一時状態: 画面選択中セル、入力途中フォーム、未確定アクション。
- 監査ログ要件: すべての行動を時刻・入力値・結果とともに `TurnLog` に保存。
- 実装済み保存形式:
  - `game_sessions`: `%Excavation{}` と `%SiteState{}` のセッション本体を保存する。
  - `artifacts`: ゲーム内 artifact 情報を保存する。
  - `turn_logs`: 行動履歴を JSON payload とともに保存する。
  - `Persistence.save!/1` / `Persistence.load!/1`: DB とゲーム構造体を往復する。

## 8. UI要件（LiveView）

- 実装済み画面:
  - `/game`: 4x4グリッドのインタラクティブゲーム画面
  - `/`: `Demo.run/0` の progression / winning / losing case を表示する読み取り専用デモ画面
- `/game` 画面:
  - ステータスバー: ターン、残り行動、スコア、記録ミス、道具耐久、ゲーム状態を表示。
  - 現場ビュー: 4x4グリッドでセル選択、層進行、発見物アイコンを表示。
  - 発見物パネル: 遺物の種別、品質、状態、記録ボタン、回収ボタンを表示。
  - 操作パネル: `dig`、`end_turn`、最終レポート、選択セル情報を表示。
  - ログパネル: 直近の行動履歴を表示。
  - Catalogモーダル: 遺物ID、座標、深度、層ID、発見ターンを確認し、担当者メモを必須入力として検証する。
  - 最終レポートモーダル: 調査者名、所見、重要遺物の要約、調査日数を必須入力として検証する。
  - ゲーム終了オーバーレイ: 勝利/敗北理由とスコアを表示し、新規ゲームを開始できる。
  - ログ表示: 層混入ペナルティ、記録ミス、回収時のスコア増減を追跡できる。
- 必須操作:
  - `dig`: 指定セルの掘削を実行し、発見判定を返す。
  - `catalog`: 発見済み遺物の必須項目を確認し、担当者メモの不足表示と再入力を行う。
  - `recover`: 記録済み遺物をインベントリへ移す。
  - 最終レポート: 4つの必須項目を入力し、検証通過後にゲームを完了する。
- 表示更新方式: サーバー状態を単一ソースとして同期

## 9. 実装済み範囲

- `SiteState` に `dig` / `catalog` / `recover` / `end_turn` を実装済み
- `Excavation` にユースケース API と `game_status/1` を実装済み
- `game_status/1` は `:in_progress` / `:won` / `{:lost, reason}` を返す
- `GameSession` GenServer でゲーム状態をプロセス管理
- `RandomDiscovery` でセル×層の確率テーブルに基づく遺物発見を実装
- `/game` でセル選択、掘削、記録、回収、ターン終了、最終レポート入力/検証、ゲーム終了表示を操作可能
- `Demo.run/0` で progression / winning / losing case を確認可能
- `/` で読み取り専用デモ出力をブラウザ表示可能
- Ecto + SQLite3 の Repo と `game_sessions` / `artifacts` / `turn_logs` による保存/読込 API を実装済み
- 保存/読込 API は `GameSession` / `/game` の進行には未接続

## 10. 非機能要件

- テスト:
  - ルールごとに正常系/異常系のExUnitを作成
  - バグ修正時は回帰テストを追加
- 品質ゲート:
  - 日常ゲートは `mix quality` とする。
  - `mix quality` は `mix format --check-formatted`、警告をエラー扱いにした compile、`mix test`、`mix credo --strict` を実行する。
  - リリース前または大きめの変更完了時は `mix quality.full` を実行し、日常ゲートに加えて `mix dialyzer` を通す。
- 性能目標: 1アクション処理を200ms以内（ローカル実行基準）で完了。
- セーブ互換性: マイナーバージョン間でセーブ読込互換を維持。

## 11. 運用方針

### 11.1 Elixir Desktop 配布

- 初期配布ターゲットは macOS とする。
- Windows / Linux 向けインストーラ、コード署名、ノータライズ、自動更新は初期配布範囲外とし、macOS 版の動作確認後に別タスクで扱う。
- 配布前の確認手順:
  1. `mix setup`
  2. `mix quality.full`
  3. `MIX_ENV=prod mix compile`
  4. `MIX_ENV=prod ARCHAEOLOGY_RUSH_DATABASE_PATH="$HOME/Library/Application Support/ArchaeologyRush/archaeology_rush.sqlite3" mix run --no-halt`
- 起動確認では `/game` の新規ゲーム開始、1回以上の `dig`、終了操作、DBファイル作成を確認する。

### 11.2 セーブデータ形式と移行

- セーブデータの正本は SQLite DB とし、外部JSONファイルは初期運用では作らない。
- DB配置は `ARCHAEOLOGY_RUSH_DATABASE_PATH` で上書き可能にする。
- スキーマ変更は Ecto migration で管理し、既存セーブを壊さない追加的変更を優先する。
- 既存列の意味変更、削除、型変更が必要な場合は、移行テストと `Persistence.load!/1` の回帰テストを先に追加する。
- セーブ互換性は同一マイナーバージョン内で維持する。互換性を破る変更はリリースノートと移行手順を必須にする。
